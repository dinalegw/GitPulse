## 2. Interactive Quick-Setup Wizard (`cmd/quick.go`)

### Flow Summary:
1. **Welcome screen** — prints version, current directory
2. **Repository path prompt** — auto-detects git repo in cwd, offers as default
3. **Remote setup** — if remote `origin` exists, pulls; if not, offers to add one
4. **Commit count prompt** — "Number of commits" (positive integer, max 3 attempts)
5. **Interval prompt** — "Minutes between commits" (zero or positive integer, max 3 attempts)
6. **Commit message prompt** — "Commit message" (non-empty, max 3 attempts; auto-appends ` #%d` if missing)
7. **Summary & confirmation** — shows all settings
8. **Validation** — runs `validation.Validate(cfg)` before proceeding
9. **Execution loop** — runs commits with interval wait between each
10. **Final summary** — total created/skipped, push status, duration

### Key Details:
- **Defaults applied in wizard:**
  - `StartTime`: "09:00", `EndTime`: "18:00", `Timezone`: "Local"
  - `DryRun`: false, `LogLevel`: "info"
  - `MetadataDir`: ".gitpulse", `MetadataFile`: "activity.log"
  - `PushRemote`: "origin"
  - `MaxCommitsPerCycle`: 100, `MinimumCommitIntervalMin`: 1
- **Input validation:**
  - Shell commands (`pwd`, `ls`, `cd`, `git status`) rejected with hint
  - Single-word folder names search `~/{projects,code,repos,src,workspace,Documents,Desktop}`
  - Recursive home search up to depth 4 for single-word names
  - Dirty working tree / missing README / detached HEAD / bare repo all block with clear messages
  - README.md creation offered if missing

## 4. Validation Checks (`internal/validation/validate.go` + `repository.go`)

### Structural Validation (`Validate(cfg)`):
1. **Repository path** — must exist, be a directory
2. **Remote branch** — must not be empty
3. **Commits per day** — 1 to 100
4. **Commit interval** — 0 to 1440; must not be less than `minimum_commit_interval_minutes`
4. **Schedule window** — valid HH:MM; end > start; interval fits in window
5. **Timezone** — valid IANA name or "Local"
6. **Log level** — one of allowed levels
7. **Metadata paths** — non-empty, relative, no traversal (`..`)
8. **Message template** — must contain `%d`
9. **Max commits per cycle** — ≥ 1

### Repository Mutation Validation (`ValidateRepositoryForMutation`):
1. **Git working tree** — must be a git repo (not bare)
2. **Not bare** — rejects bare repos
3. **Branch match** — current branch must match configured `remote_branch`
4. **Clean working tree** — no tracked staged/working-tree changes
5. **Metadata path safety** — stays inside repository

## 6. Scheduler Behavior (`internal/scheduler/scheduler.go`)

### `--schedule` / `--daemon` mode (`runScheduled` in `cmd/run.go`):
- **Foreground loop** — runs indefinitely until Ctrl+C (context cancellation)
- **Timing** — computes daily events via `EventsForDay()` using `start_time`/`end_time`/`timezone`
- **Spacing** — either fixed `commit_interval_minutes` or evenly distributed across window
- **Per event** — creates exactly 1 commit, pushes once per event
- **Not demoable in short sandbox** — waits for wall-clock times; needs minutes/hours to demonstrate

### `runOnce` (default `gitpulse run`):
- Creates `count` commits immediately (default: `commits_per_day`)
- Pushes once at end of cycle
- `--dry-run` simulates without writes

## 9. Safety Confirmation for Sandbox Use

**GitPulse is safe to run unattended in a throwaway sandbox against a scratch repo.** Verified:

1. **No external network calls** — only calls local `git` binary; no GitHub API, no telemetry
2. **Validation blocks dangerous states:**
   - `ValidateRepositoryForMutation` rejects: non-git dirs, bare repos, detached HEAD, dirty working tree, wrong branch
   - `validation.Validate` rejects: missing repo path, invalid config values, path traversal attempts
3. **Isolated metadata** — all writes go to `.gitpulse/activity.log` inside the target repo; never touches source files
4. **Dry-run mode** — `--dry-run` simulates entire cycle with zero writes
5. **Local-only push target** — sandbox can use a local bare repo as "origin" (`git init --bare /tmp/fake-origin`), so push succeeds without network egress
6. **No persistent state** — config at `~/.gitpulse/config.yaml`, logs at `~/.gitpulse/gitpulse.log`; both in sandbox home directory

**Conclusion:** The sandbox pattern described in the architecture (E2B + local bare repo as origin) will work safely and correctly.

## 10. Additional Notes

- **Commit strategy:** Appends one line (timestamp + sequence) to `.gitpulse/activity.log`, stages only `.gitpulse/`, commits, pushes once per cycle
- **Push behavior:** Non-force push; if remote not configured, warns and skips push (local-only supported)
- **Error handling:** All user-facing errors include `Fix` recommendation; no panics
- **Testing:** Unit tests with fakes, integration tests with real temp repos, race detector on CI
